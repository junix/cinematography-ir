Cinematography IR

面向电影摄影规划、自动分镜、虚拟制片与 Agent 编排的分层中间表示。保存意图、空间、约束与执行参数，而非把美学简化为公式。

产品定位

Cinematography IR（cinematography-ir）是一套用 Rust 实现的电影摄影中间表示与静态分析工具链。 它不做物理渲染，也不做几何求解——而是把戏剧意图、场面调度、镜头设计、相机程序、连续性约束五层信息结构化， 供人工与 Agent 审查、修改、编译和比较镜头方案。

项目同时提供完整的中文 mdBook 摄影教材（14 章：从成像原理、景别构图到连续性分析与 IR 架构）， 以及 cine-ir 命令行工具，用于验证、分析、检视、归一化和 Schema 生成。

验证与分析步骤

  1. 加载与反序列化：io::load_project 依据扩展名选择 YAML/JSON 解析器，deny_unknown_fields 拒绝拼写错误（如 focal_lenght_mm）。
  2. 项目级校验：检查 schema_version、项目 ID 非空、帧率合法、至少一个场景、场景 ID 唯一。
  3. 场景级校验：遍历 subjects / markers / axes / beats / lighting_setups，校验 ID 唯一、引用存在、数值有限、关键帧严格递增。
  4. 镜头时间线校验：按 start 排序后检查重叠（error）与间隙（warning），首帧是否从 0 开始，尾帧是否覆盖场景时长。
  5. 单镜头校验：景别、构图、相机状态（镜头/对焦/曝光）、运镜操作范围（镜头局部半开区间）、连续性注解引用。
  6. 连续性分析：相邻镜头对检查 180° 轴线翻转、银幕方向反转、30° 小角度切换、互反视线同向——若声明 bridge / spatial_reset / jump_cut 则豁免。
  7. 诊断输出：文本或 JSON 格式，含错误码、路径、消息与修复 hint；--deny-warnings 可将 warning 提升为非零退出码。

模块说明

src/model.rs

数据模型

~880 行，核心 IR 类型定义。CineProject 为根，向下包含 Scene、Shot、CameraPlan、ContinuityAnnotations 等。

  • CineProject / Scene / Shot 三层容器
  • NarrativeIntent：戏剧问题 + 情绪弧
  • Subject / Marker / BlockingTrack
  • Framing + Composition（9 种构图策略）
  • CameraOperation（18 种运镜枚举）
  • LightingSetup + LightSource（8 种光源角色）
  • TargetRef：Subject / Marker / Point 三态
src/validate.rs

结构验证

~990 行，结构性与语义性验证。返回 ValidationReport，区分 error 与 warning。

  • ID 唯一性（场景/人物/标记/轴线/镜头/灯光）
  • 引用完整性（subject/marker/axis/lighting）
  • 数值合法性（有限、正、归一化、快门角 ≤360°）
  • 时间线有效性（半开区间、运镜不越出镜头）
  • 编辑时间线（重叠=错误、间隙=警告）
  • 运镜操作参数校验（18 种逐分支）
src/analyze.rs

连续性分析

~215 行，跨镜头连续性启发式检查。4 条规则 + 例外桥接机制。

  • CONTINUITY_AXIS_CROSS：轴线侧翻转
  • CONTINUITY_SCREEN_DIRECTION_FLIP：银幕方向反转
  • CONTINUITY_SMALL_ANGLE_CUT：<30° 同景别切换
  • CONTINUITY_EYELINE_MISMATCH：互反视线同向
  • 豁免：bridge / spatial_reset / direction_change_visible / jump_cut
src/diagnostic.rs

诊断系统

~95 行，统一诊断结构。可序列化为 JSON 供机器消费。

  • Diagnostic：code / severity / path / message / hint
  • Severity：Error / Warning 两档
  • ValidationReport：集合 + 计数 + 扩展
  • 支持 schemars 生成 JSON Schema
src/io.rs

输入输出

~35 行，基于扩展名的格式分派。

  • load_project：.yaml/.yml/.json 自动识别
  • save_project_json：pretty-printed JSON
  • 统一 anyhow::Result 错误链
src/report.rs

摘要渲染

~95 行，人类可读的镜头清单输出。

  • 项目 / 场景 / 镜头三级摘要
  • 帧率换算秒数
  • Coverage 角色 + 景别 + 器材 + 运镜列表
  • 供 cine-ir inspect 使用
src/main.rs

CLI 入口

~140 行，cine-ir 二进制，基于 clap derive。

  • validate：全量验证 + 连续性分析
  • analyze：仅连续性分析
  • inspect：打印人类可读摘要
  • normalize：YAML→规范化 JSON
  • schema：从模型生成 JSON Schema

cine-ir CLI 子命令

validate 结构 + 语义 + 连续性全量验证；--json / --deny-warnings

设计原则与边界

核心理念

  1. 语义优先：不只存 position(t)，还要存"为什么移动"——运镜是显式操作对象（dolly/zoom/orbit/...），带叙事目的和 Coverage 角色。
  2. 显式例外：连续性是启发式诊断而非艺术禁令。bridge、spatial_reset、direction_change_visible、jump_cut 用于声明合理越轴。
  3. 严格字段：deny_unknown_fields 全局开启，拼写错误直接失败，不会静默降级为默认值。
  4. 半开区间：所有时间范围统一 [start, end)，镜头运镜使用镜头局部帧坐标。
  5. 坐标系自描述：文件自带单位、手性、上轴、前轴定义，适配器不得假设 Blender/Unreal/Three.js 约定一致。
  6. 核心与后端解耦：IR 只做交换与静态分析，几何求解/物理渲染/烘焙轨迹属于 compiler/solver/backend 层。

示例 YAML 速览

三镜头对话覆盖（master → Alice CU → Bob CU），含 180° 轴线观察与互反视线注解。

schema_version: "0.1"
id: interview_scene
title: "审讯室：三镜头对话覆盖"
frame_rate: { numerator: 24, denominator: 1 }
scenes:
  - id: interrogation
    duration_frames: 240
    narrative:
      dramatic_question: "Alice 是否会承认她拿走了钥匙？"
      emotional_arc: [{ frame: 0, label: "克制" }, { frame: 160, label: "逼问" }]
    subjects: [alice, bob, table]        # 人物 + 道具
    axes: [dialogue_axis: alice → bob]  # 关系轴线
    blocking:                           # 两人物各自动作轨迹
    beats: [establish_power, alice_hesitates, bob_pressures]  # 戏剧节拍
    lighting_setups: [cold_interrogation]  # 冷色顶灯 + 弱补光
    shots:
      - master_two_shot [0..80)    # 全景：建立空间，对称构图，tripod
      - alice_close_up [80..160)   # 特写：三分法，dolly 推进 0.35m
      - bob_close_up [160..240)    # 反打：低角度，施压感
    # 连续性：三镜均在轴线同侧(positive)，视线互反，无越轴
