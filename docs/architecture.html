01 · 它是一个编译器，不是渲染器

Cinematography IR（命令行工具 cine-ir）把电影摄影的镜头语言编译成视频生成模型的输入。作者在 YAML 里写场景、人物走位、运镜和连续性注记；验证器拦下自相矛盾的部分，求解器把「推轨 + 变焦」这类语义命令展开成逐帧相机轨迹；最后所有信息收敛成一份编译产物，供四条下游分别读出文本命令、审片图、Blender 白模多通道视频和验收报告。

它服务三类人：写分镜与运镜的创作者（用 YAML 和审片图检查自己的镜头设计）、搭视频生成管线的工程师（拿条件信号喂模型、拿约束做验收）、以及编排拍摄的 Agent（IR 保存的是意图、空间、约束与例外，机器可以审查和修改）。核心价值一句话：镜头语言从此可验证、可比较、可再生成——「大白鲨」那个著名的反向推轨变焦镜头，在这个仓库里是一份 8 秒的 YAML，过一遍编译就能量化判定主体尺度是否稳定。1

01 · 换个视角「窄腰」借自编译器的中间表示：LLVM 不让每个前端直连每个后端，中间放一层共同语言。这里的编译产物就是那层。它不是格式转换器——转换不保留「为什么这个镜头存在」。

与替代方案的差异在两个方向上：向上，它不假装是成片渲染器——Blender 只渲染可区分的黏土白模和条件通道，不追求画面好看；向下，它不把摄影美学压成公式——越轴可以显式声明为故意，验证给的是诊断启发式，不是艺术禁令。

容易混淆的边界
这个系统既不生成视频，也不渲染最终画面。它生成的是「喂给视频模型的条件」和「验收生成结果的尺子」；画面本身由外部模型产生。
语言与构建
Rust 2021，单二进制 CLI；serde 处理 YAML / JSON，schemars 导出 JSON Schema，resvg 支撑内置 PNG 编码。
外部运行时
仅执行环节需要 Blender（5.2 LTS 实机验证过）；无 Blender 的 CI 用桩脚本走完同一控制流。
形态
无服务、无数据库：纯库 + CLI，一份 YAML 从进到出都是本地文件。
配套
仓库自带 15 章中文摄影教材（mdBook）与 7 个可运行的镜头示例。

02 · 功能与特性

  • 分层语义 IR——叙事意图、场面调度、镜头设计、相机程序、连续性注记写进同一份 YAML，高层「为什么」与低层「每帧参数」同时保留。写分镜时用。
  • 结构与语义验证——空 ID、悬空引用、非法帧区间、未知字段直接报错；打错字段名会在加载时失败，不会静默用默认值。写完先跑一遍。
  • 连续性分析——180° 轴线翻转、银幕方向突变、互反视线同向、30° 以内的相似切换，都给 warning；例外用 bridge 一类的显式注记表达。
  • 运镜求解——18 种运镜（推轨、摇移、跟拍、升降、反向变焦……）编译成逐帧相机轨迹；draft 档确定性运动学，full 档追加云台限速与代理碰撞。
  • 编译窄腰——一次编译产出 Compiled Guidance IR：意图、阶段、世界与屏幕双空间轨道、19 种可观察约束、自动派生的禁止条件。所有下游共用这一份。
  • 文本 prompt 方言——IR 枚举经方言表映射成摄影词汇；主体「颜色进图、名字进 prompt」，身份绑定量化。
  • 审片视图——同一份画布出 SVG / PNG / ASCII / HTML / Markdown 六种编码、六种阅读意图（分镜板、运动语法、连续性、干净控制图……），ASCII 也能看同一张图。
  • Blender 白模执行——一次导出 10 个条件通道（深度、法线、ID、光流、骨架姿态……），原子发布 manifest，失败保留现场。
  • 闭环验收——compare 同时测世界轨迹与观众可见的屏幕结果，按逐条约束给 PASS / FAIL / INDETERMINATE，不给一个笼统的 RMSE。

03 · 分层与组成

整个系统是四层的一根垂直主线：语义 IR 进，逐帧求解接住，编译窄腰收敛，四条下游读出。分层图上同时亮起的盒子互不依赖，先后亮起的有依赖——进场动画本身在讲这棵依赖树。

每层只做一件事。CineProject 是作者手里的语义 IR，五类信息（叙事、调度、镜头、相机、连续性）都在这一层写；solve 把运镜命令展开成逐帧轨迹，出问题会带几何诊断（主体在相机背后、出了视场、轴线侧不一致）；CompiledProject 是全场唯一被下游共享的编译产物，双描边标出它是这张图的骨干；底部四条下游里只有 execute 要跨出去找 Blender，其余三条都是纯函数。交互走查：点任何一个盒子跳到讲它的段落；悬停 compiled，四条扇出边一起亮——「谁都只认窄腰」这件事一眼可见。

主走查 · YAML 进窄腰

用仓库里真实存在的示例走一遍全程，六个环节：

  1. 写——作者编辑 examples/jaws_beach_dolly_zoom.yaml：海滩场景、观察者与两个远处泳者、8 秒里第 2 到第 7 秒做反向推轨变焦。进入的是 CineProject 语义 IR。
  2. 验——cine-ir validate 与 cine-ir analyze 检查引用完整性和 180° 轴线；打错字段名在这里就报错，不会拖到渲染时才发现。
  3. 编——cine-ir compile 内部先跑 solve 得逐帧轨迹，再切阶段、投影屏幕轨道、生成 19 种约束并当场判定，落成一份 jaws-guidance.json。
  4. 读——四条下游各取所需：prompt 吐时间分段命令与负面约束；view 画审片卡；execute 生成 Blender 脚本渲染 10 个通道；compare 备好逐约束的验收清单。
  5. 回——外部模型生成视频后（轨迹估计器 TBD 尚未实现），estimate.json 交给 compare：主体画面高度是否守住 0.42、背景是否扩张，逐条给三态判定。
  6. 改——判定失败时回到第 1 步改 YAML 的意图，而不是修补输出；这是「编译器」姿态的落点。

04 · 窄腰里有什么

编译窄腰里每个镜头是一份 CompiledShot：七类信息并排存放，意图（为什么拍）、阶段（时间怎么切）、轨道（每帧在哪儿）、约束（怎么算合格）、判定（现在合不合格）、禁止（不许拿什么凑数）和剪辑关系（前后镜头怎么接）。数据形状用领域类型表达如下。

两个空间同时保留是关键设计：世界空间记「相机与主体实际在哪」，屏幕空间记「观众看见了什么」。compare 两侧都能测——生成结果可能世界轨迹全对但画面走样，也可能画面近似而机头根本没动过。流水线一节看这两份数据各自流向哪里。禁止条件在编译时自动派生：写了 dolly_zoom，就自动禁止用手持晃动、数字裁剪或演员位移来冒充。2

02 · 核对处19 种约束不是口号，是枚举点数：subject_bbox_height、reveal_visibility、focus_handoff、horizon_lock、no_camera_motion……每条自带容差；hold 与 settle 阶段还会派生出「相机不许动」的约束。

05 · 条件信号流水线

下游要回答的问题只有一个：视频生成模型吃什么。答案是三类输入槽——文本 prompt、参考图、参考视频与数值控制——恰好由窄腰的不同地层喂给。流动的粒子沿四条轨道循环：三条从窄腰出发去往输入槽，一条把生成结果带回验收。

从左往右是一条编译指令的一生。镜头 YAML 先过校验（validate / analyze 在这一步，图上由「通过校验」标注带过）交给 solve 展开逐帧轨迹，再进编译窄腰——双描边的盒子是全图唯一被四方共享的产物。窄腰右侧分三路：① 意图与阶段喂 prompt 出文本命令，② 屏幕轨迹喂 view 出审片图，③ 六条逐帧轨道喂 execute 生成 Blender 脚本；Blender 渲染的白模多通道视频与 prompt、view 的产物一起构成视频生成模型的三个输入槽。虚线边界外是外部运行时；那条虚线回边标着问号——从生成视频估计相机轨迹的估计器还没实现，compare 目前只做了比对的一半。3交互走查：悬停 compiled，三条扇出边同时亮起；四条粒子轨道分别演示三路条件信号与一条回流。compare 直读窄腰的那条边省略了，模块依赖图里画着它。

纯与非纯的边界用三问判定：会因几何失败吗（归 solve）？需要外部运行时或真实资产吗（归 execute）？只是把同一份信息重新编码吗（归纯渲染器）。「输出会动」不算执行——需要外部运行时才算。

03 · 具体例「大白鲨」示例的验收判据全部来自屏幕轨道：8 秒里 observer 的画面高度守住 ≈0.42 不变，两个背景泳者向画面边缘扩张，相机从 3.8m 退到 7.0m。约束失败改 YAML，不改输出。

06 · Blender 执行链

execute 是四条下游里唯一跨出纯函数边界的：它把六条逐帧轨道翻译成一份 bpy 脚本（坐标转换全部在 Rust 侧完成，Python 只接收 Blender 世界空间），交给 Blender 渲染白模多通道。发布是原子的——渲染先写进带进程号的工作目录，校验通过才落最终 manifest；失败时保留完整现场，不会留下貌似成功的产物。

这条链上谁在等谁。作者只发一条命令（①）；CLI 生成脚本时已经把坐标全部换算到 Blender 的世界空间（②），Python 侧不做数学；Blender 逐通道渲染 beauty、深度、法线、ID、光流、骨架姿态等十个通道，全部写进 .rendering-PID 工作目录（④）；随后脚本自己校验文件数与格式——通过就改名发布 manifest 与完成标记（⑤），失败则整个目录转成 .failed-PID 现场并附上脚本与日志（⑥）。片段框标出⑤⑥是同一校验的两个出口。没有 Blender 的 CI 环境用桩执行②至④的同一控制流，涉及 Blender 的改动仍需在真实 5.2 LTS 里过一遍。hover 或 ← / → 可逐步查看。

07 · 模块依赖

把 src 目录压到模块粒度，依赖方向全部朝下：类型与数学垫底，校验与分析读它们，求解器再往上，编译窄腰立在求解器上，四条下游与 CLI 入口最后进场。进场动画按拓扑深度错峰——同时亮起的模块互不依赖。

依赖是单向的，窄腰是汇点。垫底三层：model 定义 IR 类型，math 提供坐标系感知的基向量与投影，diagnostic 是验证与分析共用的报告结构；validate 与 analyze 分别做结构校验和连续性启发式，都只读底层；solve 把 18 种运镜展开成逐帧轨迹；compiled 立在 solve 上，是 prompt、view、execute、compare 四条下游共同的依赖，compare 直读窄腰的边就画在这里；main 是 CLI 入口，实际直连全部子命令，图里只画它到窄腰的一条代表边。悬停 compiled 看清「谁依赖它」；悬停 solve 看「它替谁扛住几何」。按预算删掉的三个薄模块：io（加载与保存）、report（人类可读摘要）、palette（主体确定性配色，view 与 execute 使用），都被 CLI 与下游直接调用，不参与分层。

08 · 取舍与边界

  • 窄腰换方言——下游只认一份编译产物，新增消费者不需要理解 YAML 的全部历史字段；代价是编译产物本身成为强契约，schema 版本（compiled-guidance-0.1）必须显式演进。
  • 三问划纯非纯——「会因几何失败吗 / 需要外部运行时吗 / 只是重新编码吗」把归属判断变成可背诵的口诀；代价是执行细节（Blender 版本差异）被推进边界之外，靠实机验证兜底。
  • 诊断不是禁令——轴线翻转给 warning 而不是 error，例外（bridge、spatial_reset、jump_cut）显式声明；代价是验证通过不等于连续性无瑕，最终裁判权在人。
  • 两档保真——draft 确定性运动学保证快与可复现，full 追加云台限速与代理碰撞；代价是 full 的物理也只是代理级别的近似，不伪装成生产级模拟。
  • 明确不做——角色外观身份保真（白模只需可区分）、视图层加载场景资产、光学畸变与真实镜头库；轨迹估计器未实现，compare 目前只覆盖闭环的一半。TBD
